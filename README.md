# CTF Tools Installer

Reproducible CTF workstation installers for Linux (Ubuntu/Mint) and Windows 11. The Linux flow creates an isolated `ctf` user and supports offline bundles plus mass deployment. The Windows flow installs native tools under `C:\CTF` and can optionally add the Linux-only pwn stack through WSL2.

## Requirements

### Linux

- Ubuntu 22.04+ or Linux Mint 21+ (apt-based)
- `sudo` access
- Internet access (or a pre-built bundle — see below)
- ~3 GB free disk (Ghidra + Burp + JtR compile + apt packages)

### Windows 11

- Windows 11 x64
- PowerShell 5.1+ opened **as Administrator**
- `winget` (Microsoft App Installer)
- Native install: at least **4 GB RAM total, 2 GB free RAM, and 8 GB free disk**
- With `-IncludeWSL`: at least **8 GB RAM total, 4 GB free RAM, and 16 GB free disk**
- Internet access; WSL2/virtualization only if `-IncludeWSL` is used

## Scripts overview

| Script | Purpose |
|--------|---------|
| `install_ctf.sh` | Creates and records a managed CTF user, then installs all tools |
| `install_ctf.ps1` | Installs the native Windows 11 toolset; optional WSL2 pwn stack |
| `uninstall_ctf.sh` | Removes the configured CTF user and their home directory |
| `make_bundle.sh` | Downloads Linux assets, including DirBuster/rockyou, and packs `bundle.tar.gz` |
| `scan.sh` | Nmap ping scan to find live lab machines, saves last octets to `ips.txt` |
| `deploy.sh` | Pushes the bundle to all machines in `ips.txt` via SSH and runs the install |
| `ansible/deploy.yml` | Ansible alternative to `deploy.sh` |
| `tests/test_install_ctf.sh` | Isolated, mocked Linux smoke/idempotence test |
| `tests/test_uninstall_ctf.sh` | Isolated Linux uninstaller safety/idempotence test |
| `tests/test_install_ctf_windows.ps1` | PowerShell syntax and dry-run contract test |

## Linux configuration

Copy `.env.example` to `.env` and fill in your values:

```bash
cp .env.example .env
nano .env
```

```
CTF_USER=ctf
CTF_PASS=your_password_here

LAB_USER=your_lab_user_here
LAB_PASS=your_lab_password_here
SUDO_USER=your_sudo_user_here
SUDO_PASS=your_sudo_password_here
IP_PREFIX=xxx.xxx.xxx
```

`CTF_USER` must use a portable lowercase Linux account name: letters, digits,
underscore and hyphen, starting with a letter or underscore (maximum 32
characters). The Linux installer and uninstaller parse `.env` as literal data; they
never execute it as shell. Exported `CTF_USER` overrides the file value, and the
installer applies the same per-value precedence to `CTF_PASS`.

## Linux single-machine install

```bash
sudo bash install_ctf.sh
```

### Direct install with curl

For a disposable, isolated lab VM, this creates the user `ctf` with password
`Ctf@2026` and records its UID and home in
`/var/lib/ctftools/managed-user`:

```bash
curl -fsSL "https://www.jurbas.com/ctf-tools/install_ctf.sh" | sudo env CTF_USER=ctf CTF_PASS='Ctf@2026' bash
```

> This shared password is public and intentionally limited to isolated lab VMs. Do not use it on an internet-exposed or shared machine.
>
> The installer finishes by running CLI checks as `ctf` for the installed tools, launchers, and wordlist. It exits non-zero if any verification fails.
>
> The installer refuses to modify an existing account unless it matches the
> root-owned ctftools state. This prevents a configuration mistake from changing
> a human or service account. Installations made before managed state existed
> must be inspected and migrated manually; the scripts fail closed instead of
> adopting them by name.

If the files generated by `make_bundle.sh` exist under `downloads/` (Ghidra, Burp, ffuf, John, DirBuster and `rockyou.txt.gz`), the script uses them instead of downloading. Otherwise it fetches them from the internet.

For Ghidra, the installer validates the pinned SHA-256 and tries the official GitHub release first, followed by the SourceForge mirror. If neither source returns the verified archive, it reports the failure, skips Ghidra, and continues installing and verifying the remaining tools.

John the Ripper is compiled from source during installation — this requires `gcc`, `make`, and dev headers (`libssl-dev`, `zlib1g-dev`, `libbz2-dev`, `libgmp-dev`), all installed automatically by the script.

Wireshark is installed non-interactively, but the installer does not add `ctf` to the `wireshark` group.

## Windows 11 single-machine install

Clone the repository, open **PowerShell as Administrator**, and inspect the plan first:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
./install_ctf.ps1 -DryRun
./install_ctf.ps1
```

Native tools are installed with pinned `winget` versions or fixed download URLs with SHA-256 verification. Direct-download tools, launchers and wordlists go to `C:\CTF`; Python packages go to `C:\CTF\venv`.

The installer performs the RAM/disk preflight before changing the machine, installs tools sequentially, disables pip cache, and removes `C:\CTF\downloads` only after a successful run. Use `-KeepDownloads` only when you intentionally want to retain roughly 700 MB of compressed archives for another run.

`pwndbg`, GDB and the supported pwntools environment are POSIX/Linux tools. To install them inside Ubuntu 24.04 on WSL2:

```powershell
./install_ctf.ps1 -IncludeWSL
```

If WSL is being enabled for the first time, Windows may require a reboot. Restart and run the same command again. The Windows script deliberately does **not** create or manage a local account/password.

### Low-memory Windows VMs

WSL is opt-in because it is the heaviest part of the setup. On a VM with less than 8 GB RAM, install only the native toolset. On an 8 GB VM, you can cap WSL globally by creating `%UserProfile%\.wslconfig` before running `-IncludeWSL`:

```ini
[wsl2]
memory=4GB
processors=2
swap=2GB
```

Run `wsl --shutdown` after changing that file. The limit affects every WSL distribution for that Windows user. The installer itself never launches Ghidra, Burp or Wireshark, so their runtime memory is not consumed during setup.

Useful commands after opening a new terminal:

```powershell
ghidra
dirbuster
ffuf -V
john --list=build-info
steghide --help
ROPgadget --help
```

## Uninstall

For the default `ctf` user, or the user configured in the neighboring `.env`:

```bash
sudo bash uninstall_ctf.sh
```

To select the same custom user explicitly:

```bash
sudo env CTF_USER=teamctf bash uninstall_ctf.sh
```

The script proceeds only when the selected name, UID and canonical home match the
root-owned state created by the installer. It then terminates that UID's processes,
deletes the account and home, and verifies both disappeared. It refuses system or
duplicate UIDs, unsafe/symlinked/overlapping homes, foreign ownership, and any mount
at or below the home. A partial `userdel` keeps the state marker and returns an
explicit error instead of becoming a successful no-op. System packages (gdb, JDK,
exiftool, wireshark, steghide, etc.) remain installed because other users may depend
on them. A second run after a complete uninstall is a safe no-op.

## Mass deployment

### 1. Build the bundle (run once)

Downloads Ghidra, Burp Suite, ffuf, John the Ripper source, DirBuster and `rockyou.txt.gz`, then packs everything into `bundle.tar.gz`:

```bash
bash make_bundle.sh
```

### 2. Scan the network

Finds live machines on the subnet defined in `.env` and saves their last octets to `ips.txt`:

```bash
sudo bash scan.sh
```

Review `ips.txt` before deploying — remove any machines you don't want to touch.

### 3a. Deploy via SSH

Requires `sshpass`: `sudo apt-get install -y sshpass`

```bash
bash deploy.sh
```

Copies `bundle.tar.gz` to each machine, extracts it, and runs `install_ctf.sh` with sudo. Prints a summary of successes and failures at the end.

### 3b. Deploy via Ansible

Requires Ansible installed and inventory already configured:

```bash
ansible-playbook ansible/deploy.yml
```

Expects `bundle.tar.gz` in the repo root.

## Logging in as the CTF user

From the desktop login screen, log in as `ctf` with the password set in `.env`.

Or from a terminal:
```bash
su - ctf
```

The Python venv activates automatically and all tools are available on PATH — no extra setup needed.

## Using the tools

**Ghidra** — reverse engineering
```bash
ghidra &
```
New project → import your binary → double-click it → CodeBrowser → decompiler panel on the right.

**Burp Suite** — web exploitation
```bash
burpsuite &
```
Temporary project → Proxy tab → Open Browser → traffic flows through Burp.

**pwndbg** — binary debugging
```bash
gdb ./binary
```
pwndbg loads automatically on top of GDB. Useful extra commands: `checksec`, `cyclic`, `vmmap`, `heap`, `stack`.

**pwntools** — exploit scripting
```python
from pwn import *
p = process('./binary')      # or remote('host', port)
p.sendline(b'your payload')
p.interactive()
```

**ROPgadget** — find ROP chains
```bash
ROPgadget --binary ./binary
```

**pycryptodome** — crypto challenges
```python
from Crypto.Cipher import AES
from Crypto.Util.number import long_to_bytes, bytes_to_long
```

**ffuf** — web fuzzing
```bash
ffuf -u http://target/FUZZ -w ~/tools/wordlists/rockyou.txt
```

**John the Ripper** — password cracking
```bash
john --wordlist=~/tools/wordlists/rockyou.txt hashes.txt
john --show hashes.txt
```

**DirBuster** — directory discovery (authorized targets only)
```bash
dirbuster -H -u http://target/ -l ~/tools/dirbuster-app/directory-list-2.3-small.txt
```

DirBuster 1.0-RC1 is a legacy Java tool retained for lab compatibility. For new automation, prefer `ffuf`.

**Wireshark / tshark** — network analysis
```bash
wireshark &
tshark -i eth0 -f "tcp port 80"
```

**steghide** — steganography
```bash
steghide extract -sf image.jpg
```

**exiftool** — file metadata
```bash
exiftool suspicious_image.png
```

## How the Linux environment works

Two lines in `/home/ctf/.bashrc` handle all of this automatically on login:

```bash
export PATH="$HOME/tools:$PATH"   # makes ghidra, burpsuite, ffuf, john etc. callable by name
source "$HOME/venv/bin/activate"  # activates the Python venv with pwntools/pycryptodome/ROPgadget
```

## Safety and provenance

- Forked from [`vazleo/ctftools`](https://github.com/vazleo/ctftools); the original structure and authorship are preserved in Git history.
- Use enumeration and password-auditing tools only on systems you own or are explicitly authorized to test.
- `rockyou.txt` contains passwords from a real historical leak. It is downloaded during installation and is **not committed to this repository**.
- Downloaded Windows archives are checked against pinned SHA-256 values before extraction.
